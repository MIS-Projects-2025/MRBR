- CRM

- AI Applications
- Mobile Apps

- APIs
- Desktop Applications

Always think before coding.

--------------------------------------------------
GENERAL RULES
--------------------------------------------------

Never generate rushed code.

Always analyze the existing project first.

Never remove existing functionality unless explicitly requested.

Preserve backward compatibility.

Never overwrite working code without reason.

Always extend existing architecture whenever possible.

Prefer improving existing code instead of rewriting everything.

If requirements are unclear, ask for clarification instead of making assumptions.

Always explain your implementation plan before generating code.

--------------------------------------------------
SOFTWARE ARCHITECTURE
--------------------------------------------------

Always produce scalable, maintainable, modular software.

Follow:

SOLID Principles

DRY (Don't Repeat Yourself)

KISS (Keep It Simple)

YAGNI (You Aren't Gonna Need It)

Separation of Concerns

Dependency Injection

Clean Architecture

Layered Architecture

Repository Pattern (when appropriate)

Service Layer

Domain-driven thinking when complexity requires it.

Never place business logic inside controllers or UI components.

--------------------------------------------------
CODE QUALITY
--------------------------------------------------

Write code as if it will be maintained for the next 10 years.

Use meaningful names.

Avoid duplicated logic.

Keep methods focused on one responsibility.

Split large functions into reusable methods.

Avoid magic numbers.

Avoid hardcoded strings.

Use constants, configuration files, or enums whenever possible.

Handle all edge cases.

Never leave TODO comments in production code.

Never leave incomplete implementations.

Never generate placeholder code unless explicitly requested.

--------------------------------------------------
ERROR HANDLING
--------------------------------------------------

Always implement proper:

Exception handling

Validation

Logging

Graceful error messages

Fallback behavior

Meaningful error responses

Do not expose sensitive information.

--------------------------------------------------
SECURITY
--------------------------------------------------

Always prioritize security.

Validate every input.

Sanitize data.

Prevent:

SQL Injection

XSS

CSRF

Authentication bypass

Authorization issues

Mass assignment

Sensitive information leakage

Never hardcode credentials.

Never expose secrets.

Use secure authentication practices.

--------------------------------------------------
DATABASE
--------------------------------------------------

Design normalized databases.

Optimize queries.

Avoid N+1 queries.

Avoid SELECT *.

Use indexes where beneficial.

Use transactions for multiple updates.

Prevent deadlocks.

Use pagination for large datasets.

Use eager loading when appropriate.

Design scalable schemas.

Never perform database queries inside loops unless justified.

Handle errors consistently.

Document endpoints when needed.
